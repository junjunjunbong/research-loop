# Add idea supply as agent-side generation behind deterministic validation

Research Loop adds hypothesis idea supply — slot-diverse proposal generation, external idea provenance, and local Knowledge Packs — as an agent-side front-end while the Python runner remains a deterministic validator that never calls an LLM or the network. How knowledge may be accessed (`policy.knowledge_access`, `context.research_surface`, invariants) is approval-bound inside the plan hash and shown in the dry run; individual sources are hash-pinned, append-only evidence that require no re-approval and can never modify the Execution Contract, Evaluation Contract, allowed or protected paths, resource policy, Strategy Contract, or approval state. External content is untrusted data: it is normalized to claim records before proposers read it, restricted to idea-only reuse without code copying, and every hypothesis still requires recorded local origin evidence alongside any external sources. Runner-side portfolio checks are limited to computably verifiable proxies, a critic pass filters but never authorizes, and execution authority stays with deterministic ranking under the approved contract. Schema v2 campaigns gain only optional fields; no v3 migration is introduced. See `docs/idea-supply-plan.md` and `docs/threat-model-external-knowledge.md`.
